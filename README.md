## 1. Зорилго ба тестийн бай

«Уншлагын жагсаалт» v2.0 вэб аппыг Session-Based Test Management (SBTM) аргаар судалж, хэрэглэгчийн түвшний үйлдэл болон API-ийн хариунд тулгуурлан согогийн нотолгоо цуглуулав. Тест дизайныг гүйцэтгэлтэй зэрэг хийж, дараагийн оролдлогыг өмнөх ажиглалтаас сонгосон.

Тестийн үндсэн oracle нь багшийн Lab07 зааварт тодорхойлсон аппын зөв зан төлөв юм. Нэмэлт сан суулгах шаардлагагүй. `app.js` нь багшийн Lab07 даалгаварт хавсаргасан эх файл бөгөөд согог засах зорилгоор өөрчлөөгүй.

## 2. Аппыг ажиллуулах

```bash
git clone https://github.com/IrmuunSolo/lab7-SW-QA-test.git
cd lab7-SW-QA-test
node app.js
```

Браузераар http://localhost:3000 хаягийг нээнэ. Апп өгөгдлөө серверийн санах ойд хадгалдаг. `Ctrl+C` дарж серверийг зогсоон `node app.js`-ээр дахин асааж, браузерыг refresh хийхэд анхны гурван номтой төлөвт буцна. Зөвхөн браузерыг refresh хийх нь серверийн өгөгдлийг анхны төлөвт оруулахгүй.

3000 портыг өмнөх лабын сервер ашиглаж байвал тухайн процессыг өөрийн терминалаас зогсооно. Bug report бүрийн урьдчилсан нөхцөлийг шинээр асаасан апп дээр бэлтгэж, бусад тестийн нэмсэн номд найдахгүй.

## 3. Charter ба сонгосон аялалууд

[Charter](charter.md) нь «Судлах — Ашиглан — Илрүүлэх» гэсэн гурван хэсгээр судлах хүрээ, аргыг тодорхойлсон. Session-ээс өмнөх charter commit болон бодит session-ийн хугацааг Git түүх, session report-оор тулгаж шалгана.

| Аялал | Дүүрэг | Судалсан чиглэл | Холбогдох олдвор |
|---|---|---|---|
| Couch Potato | Зочид буудлын | Хоосон оролтоос эхэлж, ажиглалтаас үүдэн давхардал, буруу он, хайлтыг үргэлжлүүлэн судалсан | BUG-01–BUG-04 |
| Supermodel | Жуулчны | Дэлгэцийн мэдээлэл, товчны өнгө; footer-ийн холбоосыг нээж хүрээг өргөжүүлсэн | BUG-05–BUG-07 |
| Saboteur | Бүдүүлэг | Эвдэрсэн JSON бүхий API хүсэлтийн алдаа боловсруулалт | BUG-08 |

Аяллын нэр нь хатуу дараалалтай тестийн скрипт биш. Жишээлбэл, хоосон оролт зөвшөөрөгдсөнийг ажигласны дараа өөр буруу утга болон давхардсан өгөгдөл рүү шилжсэн. BUG-07 нь Supermodel-оор GUI ажиглах явцад үүдсэн холбоосын функционал шалгалт бөгөөд зөвхөн харагдах байдлын согог биш.

### API нотолгоо

BUG-08-ийн эх файлд дараах статус ба body байна:

```text
HTTP/1.1 200 OK
Content-Type: application/json
Date: Fri, 16 Oct 2026 16:21:15 GMT
```

```json
{"result":"OK"}
```

Спецификаци буруу JSON-д HTTP 400 шаардана. Алдааны result-ийн яг нэрийг заагаагүй тул зохиомол ERROR кодыг oracle болгон шаардаагүй. HTTP Date нь UTC+08:00-аар 2026-10-17 00:21:15 бөгөөд session-ийн хугацаанд багтана.

Тусгаарлан давтах хүсэлт:

```bash
curl -i -X POST http://localhost:3000/api/books \
  -H 'Content-Type: application/json' \
  --data-binary '{"title":'
```

Анхны нотолгоог дарж бичихгүй; давтан шалгалтын гаралт хадгалбал өөр файлын нэр хэрэглэнэ. API-ийн screenshot-ын оронд HTTP статусын мөртэй бүтэн текст гаралтыг үндсэн нотолгоо болгосон.

## 6. Хамрагдаагүй үлдсэн зүйлс

Түүхий тэмдэглэлд оны яг 1000/2100 хязгаар, урт текстийн layout, амжилттай устгасны дараах мессеж, олон браузерын нийцлийн талаар хангалттай баримт байхгүй. Эдгээрийг шалгасан эсвэл амжилттай болсон гэж тайлагнаагүй.

Дараагийн session-ийн charter-ийн санал: **Судлах** — оны хязгаарын validation, урт текстийн харагдах байдал, устгасны дараах төлөв; **Ашиглан** — 999/1000/2100/2101 он, бутархай болон урт текст, нэмэх-устгах дараалал; **Илрүүлэх** — хязгаарын, layout болон үйлдлийн мэдээллийн зөрчлүүдийг.

## 7. Автомат тестэд шилжүүлэх боломж

| Согог | Автомат шалгалтын боломж |
|---|---|
| BUG-01–BUG-03 | Playwright-аар форм илгээж, мөрийн тоо ба validation мессежийг шалгах |
| BUG-04 | Гарчиг/зохиолчийн том, жижиг үсгийн хувилбаруудаар хайж үр дүнг шалгах |
| BUG-05 | Бүх ном харагдах төлөвт хүснэгтийн мөрийн тоог тоолууртай харьцуулах |
| BUG-06 | Шаардсан өнгө тодорхой бол computed style эсвэл visual regression шалгалт бичих |
| BUG-07 | Холбоосыг дарж ажиллагаатай хуудас нээгдэх, алдааны хариу ирэхгүйг шалгах |
| BUG-08 | API тестээр эвдэрсэн JSON илгээж HTTP 400 шалгах; Playwright request API-аар ч боломжтой |

Эдгээр нь цаашид бичиж болох тестийн санаа; энэ лабд ийм автомат тестүүдийг хэрэгжүүлж ажиллуулсан гэж тайлагнахгүй. Хүний нүд BUG-06 шиг өнгөний зөрчлийг хурдан анзаарч болох ч зөв oracle тодорхойлсны дараа автоматжуулах боломжгүй гэсэн үг биш.

## 8. Дүгнэлт — Session debrief

Энэ session-д Couch Potato, Supermodel, Saboteur гэсэн гурван аяллын чиглэлээр аппыг судалж найман дугаарласан олдвор баримтжуулсан. Олдворын тоогоор Couch Potato хамгийн үр дүнтэй байсан бөгөөд хоосон талбар, давхардсан ном, буруу он, үсгийн том жижиг хэлбэрээс хамаарсан хайлтын BUG-01–BUG-04-ийг энэ чиглэлээр илрүүлсэн. Supermodel-ийн үеэр тоолуур ба устгах товчны өнгийн BUG-05, BUG-06-ийг ажиглаж, footer-ийн холбоосыг дагаснаар BUG-07 гарсан. Энэ холбоосын функционал шалгалт нь харагдах байдлын анхны зорилгоос өргөжсөн нэмэлт судалгаа байв. Saboteur аяллын BUG-08-д буруу JSON хүсэлт HTTP 400-ийн оронд 200 OK буцаасныг curl-ийн бүтэн гаралтаар нотолсон. Тэмдэглэлд оны яг хязгаарууд, урт текстийн layout, устгасны дараах мессежийг хангалттай судалсан баримтгүй тул эдгээрийг дараагийн session-ийн charter-т санал болгосон. Лаб 1-ийн Playwright маягийн тестээр validation, давхардал, хайлт, тоолуур, холбоосын зөрчлийг тусгай assertion бичсэн тохиолдолд барих боломжтой. Өнгөний зөрчлийг хүний нүдээр хурдан анзаарсан боловч тодорхой өнгөний oracle болон visual regression ашиглавал мөн автоматжуулж болно. API-ийн буруу статусыг UI-ээс гадна API автомат тестээр шалгах нь тохиромжтой бөгөөд энэ лабд түүнийг хэрэгжүүлсэн гэж тайлагнаагүй. Иймээс exploratory судалгаагаар шинэ эрсдэл олж, нотолгоо цуглуулаад дараа нь зорилготой регрессийн автомат шалгалтад шилжүүлэх нь хоёр аргыг харилцан нөхөх боломжтой гэж дүгнэв.

## 9. AI ашигласан тухай

ChatGPT-ийг лабораторийн алхмуудыг ойлгох, charter-ийн ноорог боловсруулах, өөрийн түүхий тэмдэглэл болон нотолгоонд тулгуурлан session report, bug report, README-ийн бүтэц ба найруулгыг сайжруулахад ашигласан. Аппын туршилтыг өөрөө хийж, бодит ажиглалт, screenshot болон curl-ийн гаралтыг цуглуулсан. AI-ийн санал болгосон тайлбарыг спецификаци, нотолгоотой тулгаж, түүхий тэмдэглэлийг хэвээр хадгалсан.
